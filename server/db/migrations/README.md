# Drizzle Migrations

Generated by drizzle-kit from `server/db/schema/*.ts`. **Do not edit by hand.**

## Updating the schema

1. Edit `server/db/schema/*.ts`
2. Generate a new migration:
   ```bash
   npm run db:generate -- --name=<descriptive-name>
   ```
3. Review the generated SQL in `server/db/migrations/NNNN_<name>.sql`
4. Regenerate the schema snapshot:
   ```bash
   ./scripts/regenerate-schema-snapshot.sh
   ```
5. Commit both the migration and the updated `__snapshot__.sql`

## Drift detection

`server/db.schema-roundtrip.test.ts` runs in CI and fails if migrations applied to a fresh DB produce a schema that doesn't match `__snapshot__.sql`. This forces explicit review of any schema change.

## Baseline note

`0000_baseline_v10.sql` captures the schema as it existed at Drizzle adoption. The production DB was stamped into `__drizzle_migrations` during the one-time Drizzle cutover so the baseline isn't re-run on it; fresh DBs apply it from scratch. The one-off stamping script was removed post-cutover (see git history if a legacy v9 DB ever needs re-stamping).
